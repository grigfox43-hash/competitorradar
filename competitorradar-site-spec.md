# Техническое задание на разработку сайта с нуля — CompetitorRadar

> Полная спецификация для AI-агента/команды разработки, реализующей сайт сервиса **с нуля**.
> Документ описывает архитектуру, стек, страницы, данные, интеграции, монетизацию и дизайн-систему.
> Это исполняемый техзадание (runbook), а не только концепт — каждый раздел должен быть достаточным для старта кодирования без дополнительных уточнений.

---

## 0. Суть продукта

**CompetitorRadar** — AI-разведчик, который следит за изменениями на сайтах конкурентов и присылает главное в Telegram.

**Позиционирование:** «AI-разведчик, который следит за изменениями на сайтах конкурентов и присылает главное в Telegram».

**Целевая аудитория:**
- Директора по маркетингу (CMO)
- Продуктовые менеджеры
- B2B-фаундеры

**Ключевая ценность:** не нужно вручную мониторить сайты конкурентов — сервис сам парсит их, сравнивает с прошлой версией через LLM, отфильтровывает шум (баги, косметику) и присылает только существенные изменения (цены, новые фичи, офферы, контент) прямо в Telegram/Slack.

## 1. Архитектура и стек

### 1.1 Компоненты системы

| Слой | Технология | Назначение |
|---|---|---|
| Frontend (маркетинг + дашборд) | **Next.js** (App Router) или **Remix** | Публичный лендинг + авторизованный дашборд, SSR/ISR для SEO лендинга |
| Парсинг сайтов | **Firecrawl API** (основной) или **Crawl4AI** (self-hosted fallback) | Превращение произвольного URL в чистый Markdown без баннеров/шаблонного мусора |
| Оркестрация/крон | **n8n** (self-hosted или n8n Cloud) | Cron-триггер (каждую полночь по таймзоне пользователя/UTC), workflow парсинга и сравнения |
| LLM-сравнение | **OpenAI GPT-4o/4.1** или **Anthropic Claude** через n8n LLM-ноду | Промпт-сравнение snapshot вчера/сегодня, классификация изменений |
| База данных | **PostgreSQL** (Supabase или Neon) | Пользователи, конкуренты, snapshot-история, алерты, подписки |
| Аутентификация | **Auth.js (NextAuth)** или **Clerk** | Email/OAuth-логин |
| Уведомления | **Telegram Bot API**, опционально **Slack API** (Enterprise-тариф) | Доставка алертов |
| Биллинг | **Stripe** (Billing/Checkout + Webhooks) | Per-URL подписка, тарифные лимиты |
| Хостинг frontend | **Vercel** | Деплой Next.js/Remix |
| Хостинг n8n | **Railway/Render/VPS** | Воркфлоу-раннер |
| Файловое хранилище истории | PostgreSQL (JSON/Markdown snapshot) + опционально S3 для больших дампов | Хранение истории версий страниц |

### 1.2 Схема потока данных (текстовая диаграмма)

```
[n8n Cron: 00:00 UTC ежедневно]
        │
        ▼
[Получить список активных URL из БД (по всем пользователям/тарифам)]
        │
        ▼
[Firecrawl/Crawl4AI: спарсить каждый URL → чистый Markdown]
        │
        ▼
[Сохранить snapshot в БД: competitor_snapshots (url_id, date, content_markdown)]
        │
        ▼
[Достать snapshot за "вчера" для того же URL]
        │
        ▼
[LLM-нода: промпт сравнения (см. 1.3)]
        │
        ├─ Разница НЕ существенна → лог, ничего не отправлять
        │
        ▼ Разница существенна
[Записать alert в БД: alerts (url_id, type, summary, diff, created_at)]
        │
        ▼
[Проверить тариф пользователя: частота отправки / доступные каналы]
        │
        ▼
[Telegram Bot API: отправить сообщение пользователю]
[Slack API (если Enterprise): отправить в привязанный канал]
```

### 1.3 Промпт LLM-сравнения (эталон, использовать как системный промпт в n8n LLM-ноде)

```
Ты — аналитик конкурентной разведки. Тебе даны два Markdown-снапшота одной и той же страницы:
"ВЧЕРА" и "СЕГОДНЯ".

Задача: найти СУЩЕСТВЕННЫЕ отличия между версиями.

Существенные изменения — это:
- Изменение цен/тарифов/скидок
- Новые кейсы, лендинги, продукты, фичи
- Новые офферы, промо-акции, изменения в позиционировании
- Значимые изменения текста на главных CTA / value proposition

Игнорировать:
- Косметические изменения (изменение цвета, шрифта, вёрстки без смены смысла)
- Динамический мусор (счётчики, даты, случайные баннеры, рекламные ротаторы)
- Опечатки и мелкие правки без смысловой нагрузки
- Технические баги/сломанные ссылки

Ответ верни строго в JSON:
{
  "has_significant_change": true|false,
  "change_type": "price" | "new_feature" | "content" | "offer" | "other",
  "summary": "краткое описание изменения на русском, 1-2 предложения",
  "confidence": 0.0-1.0
}
```

## 2. Модель данных (схема БД)

```sql
-- Пользователи
CREATE TABLE users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  email TEXT UNIQUE NOT NULL,
  password_hash TEXT,
  telegram_chat_id TEXT,
  telegram_link_token TEXT UNIQUE,
  slack_webhook_url TEXT,
  plan TEXT NOT NULL DEFAULT 'solopreneur', -- solopreneur | business | enterprise
  plan_status TEXT NOT NULL DEFAULT 'trialing', -- trialing | active | past_due | canceled
  stripe_customer_id TEXT,
  stripe_subscription_id TEXT,
  created_at TIMESTAMPTZ DEFAULT now()
);

-- Отслеживаемые конкуренты/URL
CREATE TABLE competitor_urls (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES users(id) ON DELETE CASCADE,
  url TEXT NOT NULL,
  label TEXT, -- название конкурента, задаётся пользователем
  monitoring_frequency TEXT NOT NULL DEFAULT 'weekly', -- weekly | daily | realtime (зависит от тарифа)
  is_active BOOLEAN DEFAULT true,
  created_at TIMESTAMPTZ DEFAULT now()
);

-- Снапшоты страниц (история версий)
CREATE TABLE competitor_snapshots (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  competitor_url_id UUID REFERENCES competitor_urls(id) ON DELETE CASCADE,
  content_markdown TEXT NOT NULL,
  content_hash TEXT NOT NULL, -- для быстрого сравнения "изменилось/не изменилось"
  captured_at TIMESTAMPTZ DEFAULT now()
);

-- Алерты (существенные изменения)
CREATE TABLE alerts (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  competitor_url_id UUID REFERENCES competitor_urls(id) ON DELETE CASCADE,
  user_id UUID REFERENCES users(id) ON DELETE CASCADE,
  change_type TEXT NOT NULL, -- price | new_feature | content | offer | other
  summary TEXT NOT NULL,
  diff_snippet TEXT, -- фрагмент диффа для показа в ленте
  confidence NUMERIC(3,2),
  is_read BOOLEAN DEFAULT false,
  delivered_telegram BOOLEAN DEFAULT false,
  delivered_slack BOOLEAN DEFAULT false,
  created_at TIMESTAMPTZ DEFAULT now()
);

-- Индексы
CREATE INDEX idx_snapshots_url_date ON competitor_snapshots(competitor_url_id, captured_at DESC);
CREATE INDEX idx_alerts_user_created ON alerts(user_id, created_at DESC);
```

## 3. Тарифы и лимиты (Per-URL подписка)

| Тариф | Цена | Лимит URL | Частота мониторинга | Каналы доставки | Доп. возможности |
|---|---|---|---|---|---|
| **Solopreneur** | $49/мес | до 5 | Еженедельный дайджест | Telegram | — |
| **Business** | $129/мес | до 20 | Ежедневный мониторинг цен + моментальные алерты | Telegram | Приоритетная очередь парсинга |
| **Enterprise** | $299/мес | неограниченно | Ежедневный/реалтайм | Telegram + Slack | Экспорт истории изменений в CSV |

### 3.1 Реализация лимитов (бизнес-логика)

- При добавлении нового URL — проверка `COUNT(competitor_urls WHERE user_id = X AND is_active = true) < limit_by_plan(user.plan)`. Если превышен — блокировать добавление, показывать модалку upgrade.
- `monitoring_frequency` по умолчанию зависит от тарифа: Solopreneur → `weekly`, Business/Enterprise → `daily`. Enterprise может дополнительно включить `realtime` (частый polling, например каждые 1–3 часа) для отдельных URL.
- n8n workflow при выборке URL для парсинга — фильтрует по `monitoring_frequency` и дню недели/дате последнего парсинга, чтобы не парсить weekly-URL каждый день.
- Экспорт CSV (Enterprise) — эндпойнт `/api/export/alerts.csv`, доступен только при `plan = enterprise`, отдаёт всю историю `alerts` + `competitor_snapshots` по пользователю.
- Slack-интеграция (Enterprise) — поле `slack_webhook_url` в профиле, доставка через Incoming Webhook при создании алерта.
- Биллинг — Stripe Checkout (subscription mode), 3 Price ID (по одному на тариф), Stripe Webhook (`checkout.session.completed`, `customer.subscription.updated/deleted`) обновляет `plan`/`plan_status` в БД.

## 5. Детальная спецификация MVP-интерфейса

### 5.1 `/app/competitors` — Таблица конкурентов

**Элементы:**
- Заголовок страницы + кнопка **"+ Добавить URL"** (primary, справа сверху).
- Таблица со столбцами:
  | Название | URL | Частота мониторинга | Последняя проверка | Статус | Действия |
  - "Название" — редактируемый лейбл (label).
  - "Частота мониторинга" — badge (`Еженедельно`/`Ежедневно`/`Реалтайм`), для Solopreneur — недоступно менять (disabled + tooltip "Доступно на тарифе Business").
  - "Статус" — индикатор активен/на паузе (toggle).
  - "Действия" — иконки: пауза/запуск, удалить, "посмотреть историю".
- Пустое состояние (нет конкурентов): иллюстрация + текст "Добавьте первого конкурента, чтобы начать мониторинг" + CTA-кнопка.
- Индикатор лимита: "3 из 5 URL использовано" (progress bar), при достижении лимита — кнопка "+ Добавить URL" превращается в "Улучшить тариф".

**Модалка "+ Добавить URL":**
- Поле: URL (валидация формата, обязательное).
- Поле: Название конкурента (опционально, авто-заполняется доменом если пусто).
- Селект: частота мониторинга (ограничен доступными по тарифу опциями).
- Кнопка "Добавить" → POST `/api/competitors` → сразу запускает первичный парсинг (baseline snapshot) для формирования точки отсчёта.

### 5.2 `/app/settings/telegram` — Привязка Telegram

- Блок с инструкцией: "1. Нажмите кнопку ниже. 2. В открывшемся Telegram нажмите Start."
- Кнопка/ссылка: `https://t.me/RadarBot?start={user_token}` — `user_token` генерируется на бэкенде (уникальный, привязан к `user_id`), сохраняется в `telegram_link_token`.
- Статус подключения: "✅ Подключено (@username)" или "⚠️ Не подключено".
- Кнопка "Отправить тестовое сообщение" — для проверки, что бот доставляет сообщения.
- Логика бота (Telegram Bot, отдельный сервис/webhook): при получении `/start {token}` — найти пользователя по `telegram_link_token`, записать `telegram_chat_id`, ответить подтверждением.

### 5.3 `/app/alerts` — Лента алертов

- Верхняя панель фильтров (чипы/табы): **Все**, **Цены**, **Новые фичи**, **Контент**, **Офферы**.
- Каждый алерт — карточка:
  - Иконка типа изменения (цветовая маркировка: цены — жёлтый, новая фича — синий, контент — серый, оффер — зелёный).
  - Название конкурента + URL (ссылка на оригинальную страницу).
  - Краткое summary изменения (сгенерированное LLM).
  - Раскрывающийся diff-сниппет ("Показать детали") — старая vs новая версия фрагмента.
  - Таймстамп ("2 часа назад").
  - Отметка "прочитано/не прочитано" (непрочитанные — с акцентной левой полосой).
- Пагинация или infinite scroll.
- Пустое состояние: "Пока нет алертов — как только конкуренты что-то изменят, вы увидите это здесь."

### 5.4 `/app/settings/export` (Enterprise only)

- Кнопка "Экспортировать историю изменений (CSV)" с выбором диапазона дат.
- Если тариф не Enterprise — страница показывает блокирующий оверлей с описанием фичи и кнопкой "Улучшить до Enterprise".

### 5.5 `/app/settings/billing`

- Текущий тариф + статус + дата следующего списания.
- Таблица сравнения тарифов (как в разделе 3) с кнопками "Перейти на этот тариф" (Stripe Checkout) для тарифов выше текущего, "Downgrade" — для более низких (с предупреждением о потере доступа к лимитам/фичам).
- Кнопка "Управление платежами" → Stripe Customer Portal.

## 6. Публичный лендинг — структура и дизайн

### 6.1 Секции главной страницы

1. **Header** — логотип, навигация (Как работает / Тарифы / Блог), кнопки "Войти" / "Начать бесплатно".
2. **Hero** — заголовок в духе "Узнавайте об изменениях у конкурентов раньше, чем это заметят все остальные", подзаголовок с объяснением (парсинг + AI-анализ + Telegram), CTA "Начать мониторинг бесплатно", визуализация — имитация Telegram-чата с примером алерта.
3. **Как это работает** — 3 шага: Добавьте URL конкурента → AI сравнивает версии каждый день → Получайте алерты в Telegram. С иконками/анимацией.
4. **Демо алертов** — карусель/сетка примеров реальных типов алертов ("Конкурент снизил цену на 20%", "Запущен новый кейс", "Новый оффер: бесплатный аудит").
5. **Для кого** — 3 карточки персон: CMO, Product-менеджер, B2B-фаундер, с описанием пользы для каждого.
6. **Тарифы** — 3 карточки (Solopreneur/Business/Enterprise) с фичами и CTA, выделение Business как "популярный".
7. **FAQ** — аккордеон: "Как работает парсинг?", "Не забанят ли меня конкуренты?" (нет, парсинг публичных страниц), "Какие сайты можно мониторить?", "Можно ли подключить Slack?".
8. **Финальный CTA** — "Начните следить за конкурентами уже сегодня" + кнопка регистрации.
9. **Footer** — ссылки, контакты, соцсети, копирайт.

### 6.2 Дизайн-система (лендинг + дашборд)

**Стиль:** технологичный, «разведывательный» / «radar»-эстетика — тёмная тема по умолчанию, акцентные неоновые/сканирующие элементы (метафора радара/сканера), чистый и деловой (B2B-аудитория — CMO/фаундеры, без инфантильности).

**Палитра:**
| Роль | Цвет |
|---|---|
| Фон основной | `#0B0E14` |
| Фон карточек/секций | `#111620`, `#161C28` |
| Акцент (radar-green/cyan) | `#3DFFB0` |
| Акцент вторичный (сигнал/алерт) | `#FF5C5C` (для алертов "цены"/критичных изменений) |
| Акцент синий (инфо/фичи) | `#4C8CFF` |
| Текст основной | `#F2F4F8` |
| Текст вторичный | `#8B93A7` |

**Типографика:** заголовки — **Space Grotesk** / **Sora** (жирные, технологичные), текст — **Inter**.

**Ключевой визуальный мотив:** «радар-скан» — круговая анимация сканирующей линии (как на экране радара), используется в hero-секции и как loading-индикатор во время парсинга.

**Анимации (лёгкие, деловые — не перегружать, аудитория B2B):**
- Hero: анимированная имитация Telegram-чата — сообщения "появляются" по очереди (stagger fade-in) при загрузке страницы, как будто бот присылает алерты в реальном времени.
- Декоративный radar-скан (SVG, вращающийся конический градиент `conic-gradient`) на фоне hero, `animation: rotate 4s linear infinite`, с низкой opacity (0.15–0.25), чтобы не отвлекать.
- Секция "Как это работает" — карточки шагов появляются по очереди при скролле (`IntersectionObserver` + fade-up, stagger 0.15s), соединительная линия между шагами дорисовывается (`stroke-dashoffset`).
- Карточки тарифов — лёгкий hover-lift (`translateY(-4px)` + усиление тени), выделенный тариф — статичная неоновая обводка (без излишней пульсации, деловой стиль).
- Числа/метрики (если есть блок "N сайтов мониторится", "N алертов отправлено") — countup-анимация при попадании в viewport.
- Общее: smooth scroll (Lenis), переходы на `transform/opacity`, уважение `prefers-reduced-motion`.

**Библиотеки:** Framer Motion (интеграция нативна с React/Next.js) для компонентных анимаций, GSAP ScrollTrigger — опционально для сложных scroll-driven сцен (соединительные линии, radar-scan синхронизация).

## 7. Нефункциональные требования

- **Безопасность:** валидация всех URL перед парсингом (запрет на internal/private IP — защита от SSRF), rate-limiting на добавление URL (защита от абьюза Firecrawl-квоты), хранение токенов (Telegram, Stripe) только на бэкенде, HTTPS everywhere.
- **Надёжность парсинга:** retry-логика в n8n при ошибке Firecrawl (3 попытки с backoff), fallback на Crawl4AI при систематических сбоях Firecrawl, логирование неудачных парсингов с алертом админу.
- **Масштabируемость:** очередь задач парсинга через n8n queue mode (или отдельный worker), чтобы не блокировать cron при большом числе URL; батчинг запросов к LLM.
- **SEO:** лендинг — SSR/ISR, метатеги, OpenGraph, `sitemap.xml`, семантическая разметка.
- **Мониторинг системы (не путать с мониторингом конкурентов):** логирование ошибок workflow (Sentry/n8n execution logs), алерт админу при массовых сбоях парсинга.
- **Производительность фронтенда:** LCP < 2.5s на лендинге, ленивая загрузка тяжёлых анимаций/скриптов, изображения в WebP/AVIF.
- **Доступность:** контраст текста ≥ 4.5:1 на тёмном фоне, `prefers-reduced-motion` соблюдается, вся навигация доступна с клавиатуры.
